# שירות שליחת SMS

שירות מקומי ב־ASP.NET Core 8 עם SQL Server וממשק
HTML, CSS ו־JavaScript.

כולל ספק SMS מדומה נפרד, שמירת הודעות, בדיקת סטטוס,
סינון ובדיקות אוטומטיות.

## דרישות והכנה

- Windows ו־.NET 8 SDK.
- SQL Server מקומי פועל.
- מסד בשם SmsDb וטבלאות Messages, Employees ו־EmployeePhones.
- למשתמש שמריץ את השירות נדרשות הרשאות למסד.
- בהפעלה ראשונה נדרש אינטרנט לשחזור חבילות NuGet.
- לפני ההפעלה הראשונה, יש להריץ ב־SSMS את הקובץ
  `setup.sql` מול שרת ה־SQL המקומי.

לאחר הרצת setup.sql, ניתן להריץ ב־SSMS גם את `seed.sql`.
הוא מוסיף נתוני דוגמה בלבד: עובד עם שני מספרים, מספר משותף
לשני עובדים, ועובד ללא טלפונים. אין צורך להריצו על נתונים אמיתיים.
אפשר להריץ את שני הקבצים שוב ללא מחיקה של נתונים קיימים.

מחרוזת החיבור נמצאת ב־Sms.Api/appsettings.json.
ברירת המחדל משתמשת ב־localhost וב־Windows Authentication.



TrustServerCertificate=True מיועד לסביבת הפיתוח המקומית.

לאישור תעודת הפיתוח:

```powershell
dotnet dev-certs https --trust
```

## הפעלה

מתוך תיקיית ה־Solution:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

הסקריפט מפעיל את השירות הראשי ואת הספק המדומה.
יש לעצור קודם הרצה מ־Visual Studio כדי למנוע התנגשות בפורטים.

- ממשק: https://localhost:7071/
- Swagger של השירות: https://localhost:7071/swagger
- Swagger של המדמה: https://localhost:7172/swagger

לחיצה על Enter בחלון ההפעלה הראשי עוצרת את שני השירותים.

SQL Server והכנת המסד הם תנאים מוקדמים;
סקריפט ההפעלה אינו מתקין או יוצר אותם.

## API

- POST /messages — מקבל to ו־body ומחזיר מזהה וסטטוס.
- GET /messages/{id} — מחזיר הודעה ומברר סטטוס מול הספק לפי הצורך.
- GET /messages — מחזיר רשימה עם סינון אופציונלי לפי status.
- GET /employees — מחזיר עובדים עם מזהה פנימי, שם וכתובת.
- GET /employees/{id}/phones — מחזיר רשימת מספרים ייחודיים של העובד.
  עובד ללא טלפונים או מזהה חיובי שלא קיים מחזירים מערך ריק.
  מזהה שאינו חיובי מחזיר 400.

לדוגמה:

```json
{
  "to": "0501234567",
  "body": "שלום"
}
```

201 מציין שרשומת הודעה נוצרה, ולא שההודעה נמסרה.

## מבנה הפתרון

- MessagesController — טיפול בבקשות HTTP.
- MessageService — שמירה, שליחה ועדכון התוצאה.
- MessageRepository — שאילתות SQL ישירות עם פרמטרים.
- HttpSmsProvider — תקשורת עם ספק ה־SMS.
- EmployeesController ו־EmployeeRepository — שליפת עובדים וטלפונים בלבד.
- wwwroot — ממשק המשתמש.

נבחר פתרון קטן ללא ORM, תור או שכבות כלליות נוספות.
השמירה הראשונית מסתיימת לפני הפנייה לספק;
אין טרנזקציית SQL פתוחה בזמן פעולת הרשת.

## הנחות יסוד

### ספק SMS

לחומר שהועבר לא צורף הספק המדומה שהוזכר במטלה.
בהתאם להנחיה להגדיר הנחות ולהמשיך, נכתב ספק חלופי
עם POST /sms ו־GET /sms/{id}.

המדמה מחזיר accepted ובחלוף שתי שניות delivered.
זו סימולציה בלבד. הנתונים שלו נשמרים בזיכרון
ונמחקים בהפעלה מחדש.

### עובדים

בחירת עובד נעשית לפי שם פרטי, שם משפחה וכתובת. הצירוף ייחודי
בטבלת Employees; לכל עובד מזהה פנימי שאינו מספר העובד הארגוני.
EmployeePhones מכילה מופעי טלפון עם מפתח זר לעובד, ללא UNIQUE
על מספר טלפון. אותו מספר יכול להשתייך לכמה עובדים.

במסך בוחרים עובד, ואז מספר אחד מתוך המספרים שנשלפו עבורו.
מספרים כפולים אצל אותו עובד מוצגים פעם אחת באמצעות DISTINCT.
החלפת עובד מנקה את המספר הקודם, והשליחה מושבתת עד בחירה חדשה.

POST /messages נשאר עם to ו־body. היסטוריית ההודעות נשמרת
לפי טלפון, ולא משויכת באופן קבוע לעובד. בחירת העובד היא סיוע
במסך, ואינה מגבלת הרשאות על שליחה ישירה ב־API.
אין מסך ניהול עובדים ואין שליחה לכל המספרים בבת אחת.

### ולידציה

מתקבל נייד ישראלי מקומי באורך עשר ספרות שמתחיל ב־05,
או אותו מבנה בפורמט בינלאומי שמתחיל ב־+9725.

התוכן נדרש, אינו רווחים בלבד ומוגבל ל־160 יחידות UTF-16.
זו מגבלת מוצר, ולא הבטחה למקטע SMS יחיד.
לא מומשו חישוב מקטעים או נרמול מספרי טלפון.

### סטטוסים

- pending — נשמרה הודעה ללא תוצאת ספק.
- accepted — הספק קיבל את ההודעה.
- delivered — הספק דיווח מסירה.
- failed — הספק דיווח כשל.
- unknown — אין תוצאה אמינה; ייתכן שהספק קיבל.

timeout אינו מוכיח שההודעה לא נשלחה, ולכן אין retry אוטומטי.

עדכון סטטוס נעשה ביוזמת המשתמשת באמצעות הכפתור.
נבחר עדכון ידני כדי לשמור על פשטות והיקף המטלה.
ניתן להוסיף בעתיד polling מוגבל או webhook.

## בדיקות

```powershell
dotnet test SmsSystem.sln
```

11 בדיקות: ולידציית טלפון ותוכן, גבולות אורך,
תשובת ספק תקינה ושגיאת HTTP עם ניסיון יחיד.

הבדיקות אינן דורשות שרת או מסד נתונים.
הן אינן מכסות את כל תהליך השליחה או את שאילתות SQL.

### בדיקת בחירת עובד

לאחר הרצת setup.sql ו־seed.sql:
1. בחרו את נועה כהן מחיפה ובדקו שמוצגים שני מספרים.
2. החליפו לאורי לוי מירושלים: הבחירה הקודמת מתאפסת, ומוצג
   מספר אחד שמשותף גם לעובדת הראשונה.
3. בחרו את נועה כהן מתל אביב: אין טלפונים והשליחה מושבתת.
4. בחרו עובד ומספר, שלחו הודעה ובדקו שהיא מופיעה בטבלה.

הרחבת העובדים נבנתה ונבדקה בדפדפן עם API תחליפי, כולל
החלפת עובד בזמן טעינה ותשובה מאוחרת. בדיקת SQL Server
מלאה נדרשת מקומית; אין להסיק מבדיקות אלה שהשאילתות הורצו.

## מה לא מומש ומה הייתי מוסיפה

לא מומשו מניעת כפילויות בשרת, התאוששות מקריסה,
retry, עימוד או רענון סטטוסים ברקע.

השבתת כפתור השליחה אינה מניעת כפילות ברמת המערכת.
קריסה אחרי קבלת הספק ולפני שמירת התשובה עלולה
להשאיר pending ללא מזהה ספק.

ההרחבות הראשונות יהיו idempotency, בדיקות שירות
נוספות, התאוששות להודעות תקועות וניטור.

נבחר JavaScript פשוט במקום Angular משום שהממשק
קטן ואופציונלי. לא נדרשו אימות משתמשים או deploy.
